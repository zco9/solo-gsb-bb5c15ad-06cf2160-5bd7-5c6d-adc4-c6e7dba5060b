# 舞台排练口令同步系统

面向舞台排练场景的口令（Cue）同步 Web 应用。导演编排演出序列，控制端逐条发出口令，仅目标岗位可确认；全部目标确认后才允许推进，超时与重复确认实时标记，断线重连自动恢复现场状态。进行中的口令可由**控制端撤回并纠正重发**：同一序号递增修订号、旧轮次封存为只读历史并重新开始完整确认时限，迟到的旧轮次确认与旧定时器回调一律拒绝。进行中的口令还可由**控制端暂停 / 恢复**：暂停时冻结剩余确认时长并撤销本轮计时器，各端显示暂停原因与剩余秒数，岗位确认、替岗、撤回与推进均被拒绝；恢复时沿用同一轮次按冻结余量重新计时，不累计误差。

多个控制端可同时在线，但**同一时刻只有「指挥权租约」持有者**能执行开始、推进、替岗、撤回、暂停、恢复和重置：租约由服务端按心跳续期，断线或超时自动释放，其他控制端可申请或接管已过期租约，竞争申请由服务端原子裁决；非持有者的按钮自动禁用，越权消息一律被服务端拒绝并记录。

演出进行中或已结束时，导演端仍可在**「下一场草稿」**卡片中基于已发布序列继续编排（独立的草稿版本号 + 乐观并发控制，多导演端冲突时拒绝覆盖并返回最新草稿）；当前场次始终使用开始时冻结的序列快照，草稿保存绝不改变当前口令、目标或修订档案。控制端重置时若存在草稿，必须明确选择**「沿用当前序列」（放弃草稿）或「发布草稿并重置」（原子替换下一场序列并清空草稿）**。各端顶部实时显示已发布版本号与草稿版本号。

此外提供**只读的「演出复盘」模块**（<http://localhost:3000/replay.html>）：读取 `data` 目录中**已结束场次**（`session-start` → `sequence-finished` 完整闭合的一段）的 JSONL 事件日志，列出全部场次并重建**可拖动的口令时间轴**，支持按事件类型 / 岗位筛选、1×/2×/4× 播放、暂停与任意时间点跳转；跳转后从本场起点按事件顺序**确定性重放**到目标时刻，当前口令、确认 / 超时、替岗、修订与暂停状态与顺序播放完全一致。复盘为纯读操作，不接入 WebSocket，绝不写入当前演出状态或事件日志；日志中个别损坏行只产生告警并跳过，不影响整场解析。

> **共享事件折叠内核**：复盘、场次对比与确认延迟诊断三者基于**同一份**可在 Node.js 与浏览器共用的纯函数状态机 `public/replay-core.js`（UMD 形态：浏览器经 `<script>` 得全局 `ReplayCore`，Node 经 `require` 引入同一文件）。内核按**日志行序**（不按时间戳重排）维护唯一的场次、口令与确认轮次（`attemptId`）模型，统一处理修订封存 / 重发、暂停 / 恢复（含未闭合暂停收口）、替岗（超时标记随确认权移交）、超时与迟到确认，以及旧 `attemptId` 拒绝事件的归属；任意时刻的现场都由同一状态机从场次起点折叠（`foldUntil` / `foldEvents`）得到，三个消费者只负责各自的筛选与展示。损坏或缺字段事件沿用 `replay.js` 解析层既有的告警与跳过策略，内核对残余缺字段事件仅做防御性降级、绝不抛异常。

在复盘之上还提供**只读的「场次对比」模块**（<http://localhost:3000/compare.html>）：从复盘场次列表中选择**两个已结束场次**，逐口令生成对照表。匹配键为**规范化口令文本**（NFKC 全角/半角统一、去除汉字间排版空白、折叠空白、小写）加**排序去重后的目标岗位**；再以**动态规划在保持两场原顺序**的前提下做序列对齐（类 Needleman–Wunsch / LCS）。重复键出现多种最优解时，依次按**匹配数最多 → 总序号偏移 Σ|A序号−B序号| 最小 → 左场序号优先**裁决出唯一结果。对照表逐行标出**匹配**（两场共有）、**新增**（仅右场 B）、**删除**（仅左场 A）；每个匹配项展示**从口令开始（修订重发不重置）到完成的耗时**与**超时、迟到确认、修订、暂停次数**及两场差值（B − A），**点击任一侧口令即在复盘中打开该场次并跳转到该口令发出时刻**。对比同样为纯只读：仅一个 GET 接口、复用复盘的日志解析器，不写任何日志、不连接 WebSocket。

在复盘之上另提供**只读的「确认延迟诊断」模块**（<http://localhost:3000/latency.html>）：选择一个**已结束场次**后，**逐口令展示各目标岗位的确认瀑布图**。诊断严格复用复盘只读 GET 接口拉取的事件流，按每轮的 `attemptId` **重建每次修订轮次**（撤回封存轮次与修订重发轮次分别成图），并从每个岗位的等待时长中**扣除暂停区间**（有效截止时刻相应顺延，重复暂停 / 恢复不累计误差）；**替岗后的确认计入接管岗位**（槽位仍以原目标岗位标识，标注「原岗位 ⇄ 接管岗位」），超时标记随确认权一并移交；**迟到与超时标记保留**（迟到确认条上保留超时警示，撤回时已超时 / 未确认的槽位也保留原标记）。瀑布条按墙钟时间绘制、暂停区间以斜纹段标出，条上数值为**扣除暂停后的有效等待秒数**；图中同时给出暂停区间道与「时限（扣除暂停）」参考线。支持**按岗位**（原岗位与接管岗位都可命中，非所选岗位行暗色对照）**和结果**（最终全员按时 / 含迟到 / 最终仍超时 / 发生修订 / 暂停 / 替岗）筛选，**点击瀑布条、超时 / 替岗 / 重复确认标记、暂停区间或拒绝标记即跳回复盘页对应事件**（`replay.html?file=…&run=…&t=…` 深链定位）。模块为纯只读：**不连接 WebSocket、不写入任何日志或演出状态，也不新增任何服务端接口**（仅调用既有 `/api/replay/sessions` 两个 GET 接口）。

另有**只读的「可验证复盘归档」模块**（<http://localhost:3000/archive.html>）：选择已结束场次下载**单个 JSON 归档包**——含格式版本、场次摘要、冻结序列、有效事件（保持日志行序）与逐行告警，事件流按日志顺序构造 **SHA-256 哈希链**（h₀ 为 32 字节零值，对象键递归排序、数组保序后编码为 UTF-8 canonical JSON，hᵢ = SHA-256(hᵢ₋₁ 字节串接当前事件字节)），`manifest` 保存事件数与最终摘要。页面还支持**纯本地上传校验**：文件只在浏览器中解析、绝不上传，逐项重算并校验场次边界、事件数与摘要，失败时定位首个事件索引或字段，成功时展示归档摘要。导出仅一个 GET 接口，不写日志、不连接 WebSocket。

在复盘之上还有**只读的「复盘批注簿」模块**（<http://localhost:3000/annotations.html>，也可从 <http://localhost:3000/replay.html> 的**当前播放位置**进入）：圈定同一已结束场次的一段时间（首尾吸附到事件），填写批注文本与标签。批注**只保存在浏览器 IndexedDB**，不调用任何写接口、不连接 WebSocket。区间锚点记录首尾事件 **canonical JSON 的 SHA-256 指纹及该指纹在本场的出现序号**（重复事件靠序号消歧）；重新载入日志时按指纹 + 序号重新定位，**找不到指纹或终点顺序倒置即标为失效并完整保留原文**。支持 **JSON 导入导出**：导入按批注 `id` 合并，内容一致去重，同 id 内容不同则**两份都保留并明确标记冲突**；列表可按场次、标签与有效性筛选，点击有效批注跳回复盘区间起点。批注簿内还提供**「复盘播放清单」**编辑卡片：从**有效批注勾选区间**（批注行与候选区复选框同步）、**拖拽排序**（亦可用 ↑ / ↓），清单同样**只保存在浏览器 IndexedDB**（独立库 `cue-playlists`，与批注库分离，不经服务端）。

另有**只读的「复盘播放清单」连续回放页**（<http://localhost:3000/playlist.html>）：按清单顺序**连续回放并自动跨场次切换**。播放前对每条批注**重新定位**（重放指纹 + 出现序号锚点并重新拉取场次日志），**失效或日志缺失的条目自动跳过并在页首集中列明原因**（可一键从清单移除全部跳过项，批注原文不动）。可播放段按清单顺序拼接为**一条虚拟时间轴**：每段贡献其区间时长（`endT − startT`）的累计时长，**重叠区间按清单顺序分别播放、绝不合并**（同一条批注在清单中也不会重复）。虚拟时间轴上的**拖动、点击、顺序播放与 1×/2×/4× 倍速**都按累计区间时长**线性映射回对应场次的原始相对时刻**（`localT = startT + (vt − 段起点偏移)`），现场仍由该场次事件从起点 `foldUntil(localT)` 确定性重放得到；**播放头恰好落在段边界时进入后一段**（零长区间除外——零长段仅在点击该段时精确呈现其起点事件，不占虚拟时长）。页面同样不连接 WebSocket、没有任何写接口，场次数据仅复用复盘只读 GET 接口。

技术栈：Node.js + Express + WebSocket（`ws`）+ 原生前端（无框架）。

## 快速开始（单条命令）

### 方式一：Docker Compose（推荐）

```bash
docker compose up --build
```

一条命令构建镜像并启动服务，随后浏览器访问 **<http://localhost:3000>**（服务固定监听容器 **3000 端口**，已在 Compose 中映射到宿主机 3000）。

### 方式二：本地 Node.js（≥ 18）

```bash
npm install && npm start
```

启动后同样通过 **3000 端口** 访问各页面（<http://localhost:3000/>）：

## 指挥权租约（多控制端仲裁）

多个控制端可同时打开，但**同一时刻只有租约持有者能指挥**（开始 / 推进 / 替岗 / 撤回 / 暂停 / 恢复 / 重置七类操作），其余控制端按钮自动禁用，直接发消息也会被服务端拒绝并写入日志（`lease-op-denied`）。

- **租约时长**：默认 **15 秒**（环境变量 `LEASE_TTL_SEC` 可调，5–300 秒）。持有期间页面按 租约时长 ÷ 3（默认每 5 秒）自动发送心跳续期，无需手动操作。
- **申请**：租约空闲时，在控制端顶部「指挥权租约」卡片中（可选填控制端名称）点击「申请指挥权」，服务端原子裁决——多个控制端同时申请时恰好一人获得，其余收到拒绝（`lease-acquire-denied`）。
- **状态展示**：租约卡片与状态快照实时展示**持有者与剩余有效期**（秒级倒计时）；凭证 `token` 只定向下发给持有者本人，不随快照广播。
- **释放**：持有者点击「释放指挥权」立即交还；**断线（关闭页面 / 掉线）也会立即自动释放**。
- **接管流程**：持有者心跳停止超过租约时长后，服务端**自动释放**过期租约（日志 `lease-expired`）；此时其他控制端点击「申请指挥权」（剩余 0 秒时按钮变为「接管指挥权」）即可接管（日志 `lease-acquired`，`takeover=true`）。租约未到期前无法抢夺。
- **旧连接隔离**：每次授予生成新 `token`，心跳与释放必须携带；**旧连接的迟到心跳凭旧 `token` 一律拒绝并记录**（`stale-lease-heartbeat-ignored`），绝不续活已易主的新租约。

## 使用流程

1. **导演端**：逐行填写口令内容与目标岗位（多个岗位用逗号分隔），设置确认时限（秒，3–600），点击「保存序列」。演出进行中已发布序列锁定（当前场次使用开始时冻结的快照），但可在「下一场草稿」中继续编排下一场（见下节）。
2. **控制端**：先在顶部「指挥权租约」卡片**申请指挥权**（多人同时在线时仅一人持有，见上节）。持有后点击「开始演出」发出第 1 条口令。页面实时展示每个目标岗位的状态：待确认 / 已确认 / 超时未确认 / 迟到确认，以及岗位在线情况。
3. **岗位端**：输入岗位名「上岗」（岗位名需与序列中的目标岗位完全一致，浏览器会记住）。本岗位是目标岗位时，「确认收到」按钮亮起。
4. **临时替岗**：当前口令尚有未确认目标时，控制端点击该目标旁的「⇄ 替岗」，从**在线且非本条有效目标**的岗位中选择替补并确认。接管后：原岗位立即失去本条确认权（页面划线标注「已由 ×× 接管」），替补岗位端出现「临时替岗」接管提示并可确认，其确认计入全员确认与推进条件；超时未确认标记也随确认权一并移交。替岗**仅对当前口令生效**，推进到下一条后仍使用导演编排的原目标。
5. **推进**：仅当当前口令的**全部有效目标**（含替补）都确认后，控制端才能推进到下一条；否则服务端拒绝并提示未确认岗位。
6. **撤回并纠正重发（修订）**：当前口令**仍在进行且尚未全员确认**时，控制端在「撤回并纠正重发」卡片中填写**撤回原因**（必填）与**修正版口令文本**（必填）后提交。服务端：
   - 将旧轮次的确认、超时未确认、临时替岗、起止/截止时间整体封存为**只读历史**（不可再修改）；
   - 在**同一序号**上把修订号 `revision` 从 1 递增（2、3…），替换口令文本并记录撤回原因；
   - 清空本轮全部状态，生成新的轮次凭证 `attemptId`，**重新开始完整确认时限**；
   - 迟到到达的旧轮次确认（携带旧 `attemptId` 或不带 `attemptId`）、旧超时定时器回调、旧替岗请求一律**拒绝并写入日志**（`stale-confirm-ignored` / `stale-timeout-ignored` / `stale-substitute-ignored`），绝不污染新轮次。

   岗位端确认时必须携带其最新状态快照中的 `attemptId`。控制端与岗位端实时展示**当前修订号、撤回原因及各旧轮次的只读结果**（已确认/迟到/超时/未确认及替岗关系），断线重连后经全量快照恢复，完全一致。**已推进或已完成（含全员确认完成）的口令不可撤回**；已完成的轮次同样封存为只读历史。
7. **暂停 / 恢复当前口令**：当前口令**仍在进行且尚未全员确认**时，控制端在「暂停 / 恢复当前口令」卡片中填写**暂停原因**（必填）后点击「暂停当前口令」。服务端：
   - **冻结剩余确认时长**（`remainingMs`，已超时则余量为 0）并**撤销本轮计时器**，暂停期间超过原时限也不会标记超时；
   - 各端实时显示**暂停原因与冻结的剩余秒数**（顶部横幅 + 倒计时区），岗位确认、临时替岗、撤回重发与推进**一律被拒绝**（暂停中的确认尝试写入日志 `paused-confirm-rejected`）；
   - 点击「恢复口令」后**沿用同一 `attemptId`**（不生成新轮次），按冻结余量重排截止时间重新计时，重复暂停 / 恢复**不累计误差**；旧定时器回调凭轮次凭证与定时器令牌双重校验，只能被拒绝并记录（`stale-timeout-ignored`），绝不写入超时状态。

   暂停与恢复均写入事件日志（`cue-paused` / `cue-resumed`），包含**操作者、原因与发生时间**；暂停状态随全量快照下发，**断线重连后各端恢复一致的暂停现场**。已全员确认的口令不可暂停；已超时但未全员确认的口令可暂停（余量冻结为 0）。
8. **重置**：控制端「重置场次」清空口令进度、全部修订档案与暂停状态（事件日志保留）。若导演端保存了**下一场草稿**，重置前必须在弹窗中明确选择草稿处理方式（见下节）。

## 下一场草稿（演出中 / 结束后继续编排）

演出**进行中（active）或已结束（done）**时，导演端的「📝 下一场草稿」卡片自动出现，可基于已发布序列编辑下一场：

- **与本场完全隔离**：草稿保存在独立存储中，**绝不替换当前口令、目标岗位，也不触碰修订档案（cueHistory）、确认/超时/替岗/暂停状态**。当前场次始终使用演出开始时冻结的序列快照；各端「当前口令」与草稿内容互不影响。
- **草稿乐观并发（revision）**：每次保存携带其编辑所基于的草稿版本号 `revision`（首次为 `null`，服务端创建第 1 版，之后每保存一次 +1）。服务端**仅接受与当前草稿版本一致的写入**；多导演端并发时，过期写入被拒绝，定向下发 `draft-conflict` 并附带**服务端最新草稿**，页面自动载入最新内容，用户刷新后在其基础上重做。本机未保存的输入不会被他人新版本静默覆盖（页面给出「载入最新草稿」提示条）。
- **重置时二选一**：控制端点击「重置场次」时若存在草稿，服务端拒绝无选择的重置（`reset-choice-required`），前端弹窗要求明确选择：
  - **沿用当前序列**（`resetMode: 'keep'`）：按现有已发布序列重置回待开始，草稿被明确放弃并清空（日志 `draft-discarded`）；
  - **发布草稿并重置**（`resetMode: 'publish'`）：**原子替换**下一场序列（同一处理步骤内替换 `sequence`、递增已发布版本号、清空草稿、重置全部进度与修订档案，口令重新分配 id），随后开始的即草稿序列（日志 `draft-published`）。
- **版本号实时可见**：每个页面顶部状态条显示「🔒 已发布序列版本 vN」（导演端保存序列或发布草稿时递增）与「📝 下一场草稿：第 M 版（基于已发布 vN）」，随全量快照广播，断线重连一致。
- 草稿还记录独立的下一场确认时限（3–600 秒，缺省回退默认 30 秒）；草稿事件 `draft-created` / `draft-saved` / `draft-save-conflict` / `draft-published` / `draft-discarded` 全部写入事件日志。

## 演出复盘（只读回放已结束场次）

打开 <http://localhost:3000/replay.html>（首页「演出复盘」卡片同入口）。复盘完全基于 `data/events-<场次ID>.jsonl` 历史日志，**只读**：不建立 WebSocket 连接、没有任何写接口，绝不影响当前演出状态、绝不追加或修改事件日志。

- **场次列表**：服务端扫描 `data` 目录，逐行解析每个 JSONL 文件并切分运行段，只列出**完整闭合**（`session-start` → `sequence-finished`）的已结束场次；开始后被 `session-reset` 中断、未闭合的段不列出。同一日志文件中若含多场（多次开始 / 结束），按段分别列出。列表展示开始 / 结束时间、口令数、事件数、时长与确认时限。
- **坏数据容错**：逐行解析，任意一行损坏（非法 JSON、缺少 `ts` / `event`、`detail` 不是对象等）只生成一条告警（行号、原因、坏行原文摘要）并跳过该行，后续行继续解析，**整场复盘绝不因一行坏数据中断**。列表页汇总各文件的坏行数量，单场页顶部展示本场行区间内的坏行详情。
- **可拖动口令时间轴**：按口令绘制条带、按事件绘制彩色标记；点击 / 拖动时间轴即可**跳转到任意时刻**，点击事件列表中的某行也可跳到该事件。
- **筛选**：事件类型支持「全部分类 / 某个分类整组 / 某个具体事件」，岗位下拉含本场涉及的全部岗位（取自 `position` / `from` / `to` / `targets` / `missing`）。筛选只影响时间轴标记与事件列表的显示，不影响重放状态（状态始终基于全部事件重建）。
- **播放控制**：▶ 播放 / ⏸ 暂停、⏮ 回到起点、**1× / 2× / 4×** 速度切换；空格键播放暂停，← / → 前后跳转 1 秒。
- **确定性重放（跳转一致性）**：任何时刻的现场都由同一个纯函数 `foldUntil(events, targetT)` 从**本场起点**按事件先后逐事件折叠得到——正常播放与拖动跳转走的是同一条计算路径，因此跳转到任意时刻后，**当前口令、岗位确认 / 超时 / 迟到确认、临时替岗（含超时标记移交、不串到下一条）、撤回修订（旧轮次只读封存、修订号递增、本轮状态清空）、暂停 / 恢复状态**都与顺序播放到该时刻严格一致；同一目标时刻重复重放结果完全相同。
- **现场展示**：当前口令文本（修订后显示最新文本与撤回原因、原始口令置灰对照）、修订号、暂停横幅、各岗位「已确认 / 迟到确认 / 超时未确认 / 待确认」分组、替岗关系、已封存历史轮次（撤回 / 完成）、以及整张口令序列的完成进度。

复盘只读 HTTP 接口（均为 GET）：

- `GET /api/replay/sessions`：`{ sessions: [{ fileId, runId, startedAt, finishedAt, durationMs, cueCount, eventCount, timeoutSec }], fileWarnings: { [fileId]: { count, samples } } }`
- `GET /api/replay/sessions/:fileId/:runId`：`{ session, timeoutSec, sequence, events, positions, warnings, fileWarningCount }`；事件保持日志行序并附相对本场起点的毫秒偏移 `t`。`fileId` 强制 UUID 形状（杜绝路径穿越），非法 / 不存在返回 400 / 404。

复盘页还支持深链定位：`replay.html?file=<fileId>&run=<runId>&t=<毫秒>` 打开单场后直接跳转到相对本场起点 `t` 毫秒的时刻（场次对比页的「点击跳转」即使用此链接）。

## 场次对比（只读对照两个已结束场次）

打开 <http://localhost:3000/compare.html>（首页「场次对比」卡片同入口）。对比完全基于 `data/events-<场次ID>.jsonl` 历史日志，**只读**：页面不建立 WebSocket 连接、只有一个 GET 接口，服务端复用复盘模块的逐行解析器，绝不影响当前演出状态、绝不追加或修改事件日志。

- **选择场次**：左右两个下拉均来自复盘场次接口（只含 `session-start` → `sequence-finished` 完整闭合的已结束场次），不能选择同一场；点击「生成逐口令对照表」。下拉旁的「↗ 在复盘中打开」可单独打开任一场。支持 URL 预选：`compare.html?a=<fileId>/<runId>&b=<fileId>/<runId>`。
- **匹配键**：先以**规范化口令文本**（NFKC 全角 / 半角统一、删除汉字两侧排版空白、折叠连续空白、去首尾空白、转小写）与**排序、去重后的目标岗位**构造匹配键。因此全角空格、大小写、岗位书写顺序、重复岗位等排版差异不影响匹配；口令被撤回修订时仍按本场冻结快照的**原始口令**匹配（最终修订版文本在匹配项中单独以「最终：…」展示）。
- **序列对齐**：以**动态规划**在保持两场口令原顺序的前提下对齐（匹配 / 左场删除 / 右场新增三态转移）。当重复键产生多种最优对齐时，按以下顺序裁决唯一结果：
  1. **匹配数最多**；
  2. 所有匹配对的**总序号偏移** Σ|A序号 − B序号| **最小**；
  3. 仍并列时按左场序号升序逐项比较，**左场序号优先**（左序号相同再比右序号）取最小者。
- **对照表**：逐行标出**匹配 / 新增（仅右场 B）/ 删除（仅左场 A）**，顶部给出计数汇总。每个匹配项展示该口令**从开始发令到全员确认完成的墙钟耗时**（修订重发不重置起点，暂停墙钟计入）、**超时次数、迟到确认次数、修订次数、暂停次数**，以及两场各项的**差值（B − A）**：耗时差以带符号秒数显示（暖色），异常计数增加偏红、减少偏绿、持平置灰；新增 / 删除行展示单场指标。
- **点击跳转复盘时刻**：对照表中任一侧的口令都是链接，点击即在 `replay.html` 打开对应场次并定位到该口令的 `cue-started` 时刻（相对本场起点的毫秒偏移），随后可照常播放 / 拖动查看完整上下文。

场次对比只读 HTTP 接口（GET）：

- `GET /api/compare/sessions?a=<fileId>/<runId>&b=<fileId>/<runId>`：`{ left, right, rows, summary }`。`left` / `right` 含场次摘要 `session`、确认时限 `timeoutSec` 与逐口令指标 `cues`（`seq` / `text` / `targets` / `key` / `startT` / `durationMs` / `timeouts` / `lateConfirms` / `revisions` / `pauses` / `finalText`）；`rows` 为对齐结果，每项为 `{type:'match', left, right}`、`{type:'added', right}` 或 `{type:'deleted', left}`；`summary` 为 `{leftCount, rightCount, matched, added, deleted}`。参数缺失 / 非法 ID 返回 400，任一场不存在或未结束返回 404。

## 确认延迟诊断（只读确认瀑布）

打开 <http://localhost:3000/latency.html>（首页「确认延迟诊断」卡片与各只读页顶部导航同入口；`docker compose up --build` 或 `npm start` 启动后即可访问）。诊断页**不建立 WebSocket 连接、没有任何写接口、不新增任何服务端路由**：场次数据完全复用演出复盘的两个只读 GET 接口（`GET /api/replay/sessions` 与 `GET /api/replay/sessions/:fileId/:runId`），所有计算在浏览器内由纯函数分析器 `public/latency.js` 完成。支持 URL 预选：`latency.html?file=<fileId>&run=<runId>[&position=<岗位>]`。

- **逐口令确认瀑布**：选择已结束场次后，每条口令一张卡片，按版本顺序展示该口令的**每一次确认轮次**（第 1 版与各撤回修订版；撤回轮次红色边框、完成轮次绿色边框）。每个目标岗位一行瀑布条，条长按**墙钟时间**从轮次起点铺到结果事件时刻；**暂停区间以斜纹段画在条内**，条右侧给出**有效等待秒数**（墙钟时长 − 暂停时长）与两者对照。
- **按 attemptId 重建修订轮次**：`cue-started` 开启第 1 轮，`cue-resent` 携带新 `attemptId` 开启修订轮（同序号、修订号递增），`cue-recalled` / `cue-completed` 分别把上一轮封存为 recalled / completed。旧轮次的迟到确认、旧定时器回调与旧替岗请求（`stale-confirm-ignored` / `stale-timeout-ignored` / `stale-substitute-ignored`）只作为**红色拒绝标记**贴在其原 `attemptId` 所属轮次下方，绝不计入新轮次；无法识别原轮次的拒绝事件列入场次孤立事件，不污染任何轮次。
- **暂停时长扣除**：以 `cue-paused` → `cue-resumed` 的闭合区间（同一 `attemptId`）与观察区间 `[轮次开始, 结果时刻]` 求交，从墙钟等待时长中整体扣除；有效截止时刻 = 初始时限 + 累计暂停时长（与服务端「恢复时按冻结余量重排 deadline」等价），图中虚线标出「时限（扣除暂停）」，暂停区间另在专用道中按原因着色，重复暂停 / 恢复不累计误差。
- **替岗计入接管岗位**：`position-substituted` 之后，该槽位的确认计入**替补（接管）岗位**，行标签标注「~~原岗位~~ ⇄ 接管岗位」；超时标记随确认权一并移交（先超时后替岗再确认的，行状态为迟到且保留超时警示）。替岗仅在本轮次生效，修订重发 / 下一条口令自动回到导演编排的原目标。
- **迟到与超时标记保留**：按时确认绿条、迟到确认黄条且在超时时刻保留红色 ▲ 标记、轮次结束时仍超时未确认为红条、撤回时尚未确认（未走到超时）为灰条并保留轮次「已撤回封存」结论；重复确认以 ⟳ 小刻度保留在条上（不改变状态）。
- **筛选**：**岗位**下拉含本场涉及的原岗位与接管岗位，命中岗位高亮、其余岗位行暗色保留对照（不隐藏口令卡片，便于对照同轮其他岗位）；**结果**下拉按口令最终轮次结果筛选（最终全员按时 / 含迟到确认 / 最终仍超时 / 发生撤回修订 / 发生暂停 / 发生替岗）。
- **点击跳回复盘对应事件**：瀑布条、超时 ▲、替岗 ⇄、重复确认 ⟳、暂停区间带、暂停中拒绝与旧轮次拒绝标记均为链接，点击打开 `replay.html?file=<fileId>&run=<runId>&t=<事件相对时刻>` 并定位到该事件，随后可照常播放 / 拖动查看完整上下文。

诊断纯函数分析器（`public/latency.js` 的 `CueLatency.analyzeSession`）同时以 Node 模块导出供测试复用；它只读取入参事件数组，不发起任何 I/O。

## 可验证复盘归档（只读导出与本地校验）

打开 <http://localhost:3000/archive.html>（首页「可验证复盘归档」卡片同入口；`docker compose up --build` 或 `npm start` 启动后即可访问）。归档完全基于 `data/events-<场次ID>.jsonl` 历史日志，**只读**：导出仅一个 GET 接口，不建立 WebSocket 连接、不写入任何日志或演出状态；校验完全在浏览器本地进行，**文件绝不上传到服务器**。

- **下载归档**：下拉选择已结束场次（`session-start` → `sequence-finished` 完整闭合，与复盘列表同口径），点击「下载 JSON 归档」得到单个 JSON 文件 `cue-archive-<fileId>-run<N>.json`（接口同时带 `Content-Disposition: attachment`，直接访问 URL 也会下载）。
- **归档格式**（`format: "cue-archive"`，`version: 1`）：
  - `session`：场次摘要 `{ fileId, runId, startedAt, finishedAt, durationMs, cueCount, eventCount, timeoutSec }`；
  - `sequence`：**冻结序列**（本场首次 `cue-started` 登记的口令快照，修订后的文本只反映在事件流中）；
  - `events`：**有效事件**，保持日志行序，每条原样保留 `{ ts, event, detail }`；
  - `warnings`：**逐行告警**（仅本场行区间内的坏行：`{ line, reason, raw }`）；
  - `manifest`：`{ eventCount, digest }`——事件数与事件哈希链最终摘要（64 位十六进制）。
- **哈希链**：事件按日志顺序依次入链。`h0` 为 **32 字节零值**；每个事件先做 **canonical JSON** 编码（对象键递归排序、数组保序、UTF-8 字节），再 `hi = SHA-256(h(i-1) 字节串接当前事件字节)`；`manifest.digest` 为最终摘要的 hex。任何事件内容或顺序的改动都会改变最终摘要。
- **本地校验**：选择本机归档文件后，页面在浏览器内逐项重算并校验——格式标识与版本、场次摘要字段、冻结序列与口令数一致、事件逐条结构合法、**场次边界**（首事件为 `session-start` 且时间等于 `startedAt`、末事件为 `sequence-finished` 且时间等于 `finishedAt`、场中不得再出现边界事件、时长与起止时间差一致）、**事件数**（`session.eventCount` 与 `manifest.eventCount` 均等于实际事件数）、**摘要**（本地重算哈希链与 `manifest.digest` 比对）。**失败时定位首个事件索引或字段**（如「第 3 个事件（索引 2），字段 `events[2].event`」或「字段 `manifest.digest`」）；**成功时展示归档摘要**（格式版本、场次起止与时长、口令 / 事件 / 告警计数、确认时限与最终摘要）。
- **第三方独立校验**：归档为自描述格式，任何人可按上述哈希链规则独立重算——对 `events` 数组按序做 canonical JSON（键排序、数组保序、UTF-8）并逐节串接 SHA-256，结果应等于 `manifest.digest`，且 `manifest.eventCount` 等于事件条数。

可验证复盘归档只读 HTTP 接口（GET，仅此一个）：

- `GET /api/archive/sessions/:fileId/:runId`：返回上述归档 JSON（`Content-Disposition: attachment`）。`fileId` 强制 UUID 形状（杜绝路径穿越），非法返回 400，场次不存在或尚未结束返回 404。

## 复盘批注簿（只读 · 批注仅存本浏览器 IndexedDB）

打开 <http://localhost:3000/annotations.html>（首页「复盘批注簿」卡片、复盘页顶部导航与复盘播放器内卡片同入口；`docker compose up --build` 或 `npm start` 启动后即可访问）。批注簿**没有任何服务端写接口、不连接 WebSocket**：所有批注只写入本浏览器的 IndexedDB（库名 `cue-annotations`），场次数据仅复用复盘的只读 GET 接口；导入文件只在本地解析，导出为本地生成的 JSON 文件下载。

- **从当前播放位置圈定区间**：在复盘播放器（`replay.html?file=…&run=…`）播放 / 拖动到目标位置，点击「① 圈定起点（当前位置）」，再到区间末端点「② 圈定终点（当前位置）」——位置自动**吸附到当前时刻最近的已发生事件**（同事件可构成零长区间，终点不允许早于起点）。点「③ 填写批注…」携带场次与首尾事件序号进入批注簿新建表单，可再调整首尾事件。复盘时间轴上同时以区间带展示本场批注：**有效绿色实带（点击跳到区间起点）、失效红色虚带**。
- **事件指纹锚点**：区间首尾各记录 `{ digest, ordinal }`——`digest` 为锚定事件 `{ts, event, detail}` 三字段 **canonical JSON 的 SHA-256**（对象键递归排序、数组保序、UTF-8，与归档模块同一算法；不含 `t` / 行号等派生字段），`ordinal` 为该指纹在本场事件序列中的**出现序号（1 基）**，内容完全相同的重复事件靠序号消歧。批注同时快照首尾事件原文与相对本场起点的毫秒偏移，供失效时展示。
- **重载日志重新定位（失效保留原文）**：打开批注簿时逐条重新拉取场次并构建指纹表：首尾指纹都能按序号找到且终点行序不早于起点 → 有效；**指纹找不到、出现次数不足（序号超出）、序号非法，或终点排在起点之前（顺序倒置）→ 标记失效**，列表红标「✖ 失效（原文保留）」并给出原因，批注文本、标签、圈定时的区间时间与首尾事件原文完整保留，失效批注不可跳转。场次日志本身已不存在（文件 / 段落缺失）同样按失效处理。
- **筛选与跳转**：列表支持**按场次（含日志已删除的引用场次）、标签、有效性（全部 / 仅有效 / 仅失效）及仅看冲突**筛选；**有效批注点击「↗ 跳回复盘区间起点」**即打开 `replay.html?file=…&run=…&t=<起点毫秒>` 定位到区间起点；也可在复盘页本场批注迷你列表中直接跳转。
- **批注内容**：批注文本（必填）+ 标签（逗号 / 顿号 / 分号 / 空白分隔，自动去空白、去重、保序）；批注可在本机删除（仅删本地 IndexedDB 记录）。
- **JSON 导出**：`cue-annotations-<时间>.json`，格式为 `{ format: "cue-annotations", version: 1, exportedAt, count, annotations: [...] }`；每条含 `id`（UUID）、`sessionRef`（fileId / runId / 起止时间）、`start` / `end` 锚点（指纹 + 序号）、首尾事件原文快照、`startT` / `endT`、`text`、`tags` 及冲突字段。
- **JSON 导入（按 id 合并）**：
  - 同 `id` 且**内容一致**（场次引用、锚点、区间时间、文本、标签的 canonical 比较）→ **去重**跳过；
  - 同 `id` **内容不同** → **两份均保留**：导入份改写新 id（`<原id>#imp`，再冲突递增 `-2`、`-3`…），双方都明确打上 **⚠️ 冲突** 标记并归入同一冲突组（原 id），导入完成提示冲突组数，列表中可人工核对后删除多余项；冲突标记随导出保留；
  - 库中无此 id → 直接新增；无法识别的坏记录跳过并计数。

## 复盘播放清单（只读 · 清单仅存本浏览器 IndexedDB）

在批注簿页「④ 复盘播放清单」卡片中编辑清单，在 <http://localhost:3000/playlist.html>（首页卡片与复盘 / 批注簿顶部导航同入口）连续回放。清单文档只写入本浏览器 IndexedDB 的独立库 `cue-playlists`（单例文档 `main`，条目为 `{ id, addedAt }`，仅引用批注 id），**不连接 WebSocket、没有任何服务端接口**；播放页场次数据仅复用复盘只读 GET 接口。

- **勾选与排序**：只有**有效批注**可勾选加入（批注行头部与候选区复选框同步勾选态）；同一批注不会重复入单。清单项支持 **HTML5 拖拽排序**（触屏 / 无拖拽环境可用每行 ↑ / ↓ 按钮），任何增删与排序都即时写回 IndexedDB；可一键清空（批注本身不删除）。
- **播放前重新定位**：打开播放页（或点「↻ 重新定位」）时对每条批注重新拉取其场次日志、重建指纹出现序号表并按 `{digest, ordinal}` 重新定位——与批注簿完全同口径。**批注已删除、场次日志缺失（文件 / 段落不存在）、指纹找不到 / 序号超出 / 顺序倒置**的条目**自动跳过，不进入虚拟时间轴**，并在页首面板**逐条集中列明跳过原因与批注文本**；可一键「从清单移除全部跳过项」。
- **虚拟时间轴映射**：可播放段严格按清单顺序首尾拼接（**不按场次归并、不合并重叠区间**；重叠 / 包含的两条批注各播各的）。第 i 段占据虚拟区间 `[Σ<ᵢ durⱼ, Σ≤ᵢ durⱼ)`，其中 `dur = endT − startT`。播放 / 拖动得到虚拟时刻 `vt` 后，取**第一个严格结束于 `vt` 之后的段**（因此 **`vt` 恰好落在边界时进入后一段**），再线性映射 `localT = seg.startT + (vt − seg.offsetStart)`，并用该场次全部事件 `foldUntil(events, localT)` 确定性重放当前现场——与单场复盘同一 reducer，拖动与顺序播放到达同一点必然一致。1×/2×/4× 只改变虚拟时间的推进速率（`vt += dt × speed`），不改变映射本身。跨相邻两场的边界在时间轴上以虚线刻度标注，播放头越过时自动切换场次数据。
- **零长区间**：`startT == endT` 的批注段时长为 0、不占用虚拟时长，顺序播放自然越过；点击段概览中该段（或其段带）可精确呈现其起点事件，开始播放 / 主动 seek 后恢复默认边界规则。
- **操作**：空格播放 / 暂停，← / → 在虚拟时间轴上前后跳转 1 秒；时间轴可点击 / 拖动；段带点击跳到该段虚拟起点，事件行点击跳到对应虚拟时刻；每段附「原场次复盘 ↗」链接，可回到普通单场复盘页核对。

## 核心规则

- **指挥权租约**：开始 / 推进 / 替岗 / 撤回 / 暂停 / 恢复 / 重置七类操作仅租约持有者可执行。租约默认 15 秒、按心跳续期；申请与接管的检查与授予在同一同步消息处理内完成（原子裁决，并发申请先到者得）；持有者断线立即释放，心跳停止超时自动释放；每次授予生成新 `token`，旧连接的迟到心跳 / 释放凭旧 `token` 一律拒绝并记录，绝不续活新租约。持有者与剩余有效期随全量快照下发，非持有者前端按钮禁用、服务端同步拒绝（`lease-op-denied`）。
- **岗位隔离**：只有当前口令有效目标（原目标或接管后的替补）的岗位端能确认，其他岗位的确认请求被服务端拒绝。
- **临时替岗**：仅控制端可发起，且仅当目标尚未确认；替补必须在线且不是本条有效目标。服务端仅对当前口令原子更新有效目标与确认权限，下一条口令自动恢复导演编排的原目标。替岗的原岗位、替补岗位与发生时间写入事件日志，并随全量状态同步到各端，断线重连后保持一致。
- **状态不串场**：每条口令激活时确认表、超时表与替岗表整体重置，上一条的确认与替岗绝不带入下一条。
- **撤回并纠正重发（修订轮次）**：仅控制端可发起，且仅限当前进行中、尚未全员确认的口令（已推进/已完成的口令不可撤回，全员确认完成的口令也不可撤回）。每轮确认都有服务端生成的唯一 `attemptId`，岗位端确认消息必须携带其快照中的 `attemptId`；撤回后同序号 `revision` 递增、状态清空、完整确认时限重新计时，旧轮次的确认/超时/替岗/截止时间封存为只读历史（`cueHistory`，随全量快照下发，断线重连一致），旧确认、旧定时器回调与旧替岗请求只能被拒绝并记录（`stale-*-ignored`），绝不写入新轮次状态。
- **暂停 / 恢复**：仅控制端可发起，且仅限当前进行中、尚未全员确认的口令，暂停必须填写原因。暂停时服务端冻结剩余确认时长（`remainingMs`）并撤销本轮计时器；暂停期间岗位确认、替岗、撤回与推进均被服务端拒绝。恢复时沿用同一 `attemptId`，按冻结余量重排 `deadline` 重新计时，重复暂停 / 恢复不累计误差；每个定时器都携带轮次 `attemptId` 与单调递增的 `timerToken` 双重凭证，任何旧定时器回调只能被拒绝并记录，绝不写入超时状态。暂停状态（`paused` / `pauseReason` / `remainingMs` 等）随全量快照下发，断线重连后各端一致；暂停与恢复事件记录操作者、原因与发生时间。
- **超时标记**：到达确认时限仍未确认的岗位被实时标记为「超时未确认」并写入日志；超时后仍可确认，标记为「迟到确认」。
- **下一场草稿**：仅导演端可保存，且仅在 active/done 阶段（idle 阶段直接保存序列即可）。草稿与本场冻结快照隔离，保存不改变当前口令、目标与修订档案。草稿携带独立 `revision` 乐观锁版本号：服务端仅接受与当前版本一致的写入，冲突时拒绝覆盖并随 `draft-conflict` 定向下发最新草稿供刷新重做；首次保存创建第 1 版并记录所基于的已发布版本 `basedOnVersion`。控制端重置存在草稿时必须携带 `resetMode=keep`（沿用当前序列、放弃草稿）或 `resetMode=publish`（发布草稿并重置），后者原子替换下一场序列、递增已发布版本号并清空草稿。已发布版本号 `publishedVersion` 与草稿（含版本号）随全量快照下发，各端实时显示。
- **重复确认**：同一岗位对同一条口令的重复确认不改变状态，实时写入日志并标记。
- **断线重连**：岗位端断线后自动重连（1 秒间隔），重连后服务端下发全量状态快照，恢复当前口令、倒计时与本人确认状态；控制端可看到岗位在线 / 离线。
- **事件日志**：本场所有事件（发出口令、确认、迟到、重复、超时、替岗、上下线、推进、重置等）保存在内存并追加写入 `data/events-<场次ID>.jsonl`，各页面实时滚动展示。

## WebSocket 协议简述

连接地址：`ws://<host>:3000/ws`

- 客户端 → 服务端：
  - `hello`（登记角色/岗位/clientId）、`setSequence`
  - `saveDraft`（导演端保存下一场草稿：`{ cues, timeoutSec, revision }`；仅 active/done 阶段；`revision` 为所持草稿版本，首次传 `null`，过期写入被拒）
  - `start`、`advance`
  - `reset`（控制端重置：`{ resetMode }`，无草稿时可省略/`normal`；有草稿时必须为 `keep`（沿用当前序列并放弃草稿）或 `publish`（发布草稿并原子重置））
  - `lease-acquire`（控制端申请 / 接管指挥权租约：`{ name? }`；未到期时他人申请被拒）
  - `lease-release`（持有者主动释放：`{ token }` 必填）
  - `lease-heartbeat`（持有者心跳续期：`{ token }` 必填；旧 token 一律拒绝）
  - `confirm`（岗位确认，**必须携带当前快照中的 `attemptId`**）
  - `substitute`（控制端临时替岗：`{ from, to, attemptId }`）
  - `recall`（控制端撤回并纠正重发：`{ reason, text }`，均为必填；仅限当前进行中且未全员确认的口令）
  - `pause`（控制端暂停当前口令：`{ reason }` 必填；仅限进行中且未全员确认时）
  - `resume`（控制端恢复当前口令：沿用同一 `attemptId` 按冻结余量重新计时）
  - 其中 `start` / `advance` / `reset` / `substitute` / `recall` / `pause` / `resume` 七类仅租约持有者可执行
- 服务端 → 客户端：
  - `state`（全量状态快照：含 `publishedVersion`（已发布序列版本号）、`draft`（下一场草稿：`revision` / `basedOnVersion` / `cues` / `timeoutSec` / `updatedAt`，无草稿为 `null`）、`attemptId`、`revision`、`revisionReason`、只读 `cueHistory`、`substitutions` 与 `effectiveTargets`，暂停状态 `paused` / `pauseReason` / `pausedAt` / `pausedBy` / `remainingMs`，以及租约 `lease`：`holderId` / `holderName` / `expiresAt` / `remainingMs` / `ttlMs`，任何变化即广播，重连恢复依赖于此）
  - `draft-saved`（草稿保存成功，定向下发最新 `{ draft }`）
  - `draft-conflict`（草稿乐观并发冲突：定向下发 `{ message, currentRevision, draft }`，`draft` 为服务端最新草稿，用户据此刷新重做）
  - `reset-choice-required`（有草稿却无选择地重置：定向下发 `{ message, draft }`，要求选择 keep/publish）
  - `lease-granted`（租约授予 / 重连补发，定向下发 `{ token, expiresAt, ttlMs }`，`token` 不随快照广播）
  - `lease-renewed`（心跳续期确认，定向下发新 `expiresAt`）
  - `error`（操作拒绝原因，如旧轮次确认被拒、不可撤回、口令已暂停、越权操作、租约申请被拒、草稿非演出阶段保存等）
